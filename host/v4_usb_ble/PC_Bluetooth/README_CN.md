V4 双连接电脑端：连续六键确认异常修复版

V4 电脑端连续六键修复；不需要烧录，不改PID或板端保护。

已有上次完整包的队友：
1. 先在旧窗口停止并断开全部，再关闭旧窗口。
2. 解压本覆盖包，把其中PC_Bluetooth文件夹内的文件复制到原完整包的PC_Bluetooth文件夹，选择替换同名文件。
   不要删掉原文件夹；其中的runtime、vendor_ble、vendor_serial和settings.json都保留。
3. 从原完整包的“启动窗口.cmd”重新打开。COM、蓝牙地址、G-L键位和指定键盘设置沿用原电脑保存的设置。

修复前：第一条蓝牙位置指令已经让装置转动，但确认丢失后，电脑把正常USB和其余五键一起锁住。
修复后：只有蓝牙副路的位置/取消指令确认异常时，显示蓝牙异常，后续新按键走USB；旧指令不重发，失败前未发出的蓝牙位置排队项不转USB执行。
六个位置按钮和指定键盘共用同一修复路径。后来的旧确认不会让蓝牙自动恢复位置发送；需要时可以手动断开并重连蓝牙。
若蓝牙正常，位置按键仍走蓝牙；只有USB时六键同样可用。

本修复已完成69项故障注入回归，包含丢确认、坏CRC、连续六位置、延迟旧确认；原35项双路、45项界面和119项协议检查通过。均为离线验证，队友实机尚待验证。

——基础完整包使用说明（实测记录来自修复前的本机版本）——
V4 串口＋蓝牙双连接上位机：本机已联通，并经用户确认可用

完整包已含FPGA源码、合格3A位流、电脑端源码、Python3.12、Tk/Tcl、Bleak/WinRT、串口依赖，不用安装Python或pip。

队友使用：
1. 完整解压，双击根目录“启动窗口.cmd”。不要在压缩包里直接运行，不要只复制一个.py。
2. 若板上已经是5634523A，不用重新烧录。若仍是旧版，保持停机后用Gowin Programmer加载Bitstream/J280_V4_R28_USB_BLE_5634523A_Qualified.fs，器件GW2A-55C/PBGA484，执行SRAM Program。
3. 选实际COM（可刷新、可手填，留空仅一个USB时自动选择），默认波特率230400；点击“连接USB”。USB负责常规控制、参数和数据。
4. 点击“连接蓝牙”。BT10默认D0:54:7B:AA:0C:84，可在窗口修改。两路状态分别显示“已连接，有回包”，蓝牙和USB共用同一会话。
5. 主窗口六位置按钮和默认数字1–6控制位置；蓝牙已连时走蓝牙，只有USB时照样可用。空格STOP。输入框内数字只输入，不触发位置。
6. 需要旧版指定独立小键盘时，点“指定键盘设置”，在程序内枚举设备、选唯一路径、启用；可用旧G–L六位置预设。默认不捕获指定键盘，不记录其他键盘文本。指定键盘启用后普通窗口位置键暂停，避免同一次按键重复发送。
7. COM、波特率、蓝牙地址、六个位置按键和指定键盘路径都能修改，“保存设置”记在本电脑settings.json。换电脑可重新选择，无需改源码。本包没有预置开发机COM和键盘路径。
8. 按现场流程清故障、扶直校零，再由你手动运行。启动窗口不会自动连接、校零、清故障、改PID或运行。

蓝牙要求：Windows10/11 x64、开启BLE蓝牙，同一个BT10先断开旧电脑。此次本机曾出现无线电显示开启却完全扫不到广播，关闭/开启一次本机蓝牙后恢复；若再次出现同样现象，先这样恢复扫描。程序的蓝牙定位仍沿用用户提供旧包的代码，未换掉FFE0/FFE1/FFE2连接方式。

代码复用和适配：原raw_keyboard.py字节未变；3A使用wire4/layout5，因此用已适配3A的codec，不直接混用旧版layout1。板端仍为同一个已通过验收的5634523A；本次仅更新上位机双路界面与配置，没有再次修改或编译FPGA。
角度53.78/0/210.14、位置17.67/0/616.61；角度P1ms、位置P5ms、角D5ms、位置D25ms，积分固定0。保护保持原样。

本机实测：3A已单次SRAM加载并读回；USB和蓝牙同时有回包、仅一次HELLO；用户手动操作期间记录到USB常规控制与BLE位置指令，未由自动脚本发起运行/校零/位置。键盘/路由/设置离线检查和主窗口/设置弹窗检查均已通过。
板卡断电后SRAM位流可能恢复旧Flash，需重新加载本包.fs。本包不自动写Flash。队友电脑的实际连接表现仍以队友现场为准。
