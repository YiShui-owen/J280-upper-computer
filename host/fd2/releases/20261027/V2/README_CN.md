# J280 V2 起摆、单圈及连续旋转接入修复版

本包已完成新的完整综合、布局布线和原 50 MHz 时序验收：Fmax 50.106 MHz，Setup +0.043 ns，Hold +0.213 ns，Recovery +12.105 ns、Removal +1.372 ns、Pulse +7.315 ns，违例 0。

适用 J280 / GW2A-LV55PG484C8/I7，交付标识 J280_V2_HandoffFix_20261027。本次没有连接、烧录或操作实物，未验证机械平滑性与实际光学手势识别。

## 修改与保留功能

只修复共同起摆接入逻辑：起摆源完成后等待原父级接入窗口成立，再锚定当时旋臂位置；使用原复位/prime 顺序，取得新的完整角度计算帧后允许平衡。资格丢失会重新捕获。原 250 ms 超时、STOP/急停与故障保护保留，不增加 700 ms 等待。

保留原 V2 的 SWM4 起摆（仅 profile 0）、固定 PID、手势、单圈/连续旋转、减速停止和匹配窗口。本版没有扩展成 V1 的三个起摆，也没有添加自适应。36 项实际构建输入中只有 System 改动，其他 35 项及 Host/runtime 与已验收原包逐字节相同。角度 P/I/D=49/0/251、位置 P/I/D=25/0/610、5 ms/25 ms 周期及原参数可调功能保留。

## 使用

1. 正式包整体解压到短目录，如 `D:/J280_V2`。位流位于 `V2/bitstream/J280_V2.fs`，只用于 J280 的指定器件。下载使用现场已确认流程，包内不会自动下载。
2. 双击 `Start_V2.cmd` 打开原配窗口。固件身份 `0x46443432`、wire=3、schema=`0x46443402`，UART 2 Mbaud；不可混用旧 FD1W 或其他版本窗口。
3. 按 [J280 接线说明](docs/WIRING_CN.md) 保留电机、编码器、ADC 连接。M5 U127 红线 H2-1/5 V、黑线 H2-2/GND、白线 SCL/H2-75、黄线 SDA/H2-73，INT 不接；该接法不适用于 ACG525。
4. 原套件默认配置 0：1080 物理计数/圈、映射为 1040 Forest 单位/圈；IP570 配置 1：1040 物理计数/圈、1:1 映射。先 STOP 且确认 PWM=0，再选套件并明确校零。电平、方向、线束与机械行程仍需现场确认。
5. 选择本版已有 SWM4 参数页并按原方法起摆；进入平衡后使用原窗口或手势的转圈/停止操作。操作与按键含义见 [原配说明](docs/README_CN.md)，其中其他日期的五版本历史记录不代表本次新增验收。

## 已完成的离线功能验证

- 两套编码器映射 × 正常/延迟资格：4 项、584 项检查；资格丢失恢复、真实漂移、STOP、KEY 急停、250 ms 超时、重复起摆：6 项、960 项检查。
- 两套映射分别执行两次自然起摆，使用真实 UART 请求正一圈、受控停止、反一圈、STOP 后重启：977 项检查及 16 项转圈命令检查。验证的是数字目标和状态，不声称模拟了机械完整一圈或实物收敛。
- 原版延迟资格负例复现：实际位置 -120 时仍保留早期锚点 -100、过时角度 3197 与 moto=-5488；修复后为新锚点 -120、角度 3085、moto=0。首个位置周期位置 bias/diff/PWM=0，位置 D 由绑定 bench 的 first25ms 断言验证。
- 原套件的物理 -120 对应 Forest 目标 -115，IP570 对应 -120；正确比较为同一位置单位的 target 与 motion_actual，不直接混比物理计数和 Forest 单位。

刺激来自实际 ADC/UART/合法 A/B 输入，没有 force 起摆完成或 READY；启动等待、校零与按键去抖的压缩参数见绑定仿真记录，没有机械对象模型。功能证据在 `reports/`、`evidence/handoff/`。正式包的 native 证据位于 `V2/native/`，最终验收以 `QUALIFICATION.json` 和外部交付记录为准。

可在正式包根目录复核：

```powershell
.\runtime\python.exe -B -X utf8 .\tools\verify_handoff_release.py . --variant 2 --smoke-host
```

两套实物的机械平滑/收敛、光学手势方向及外部 ADC 板级最大延迟仍未验证。

## 复现本次原生构建

本次通过的 Gowin 编译器版本：`V1.9.12.04 (64-bit)`。实际 options 为：

```json
{
  "map_option": 2,
  "opt_goal": "timing",
  "place_option": 2,
  "route_maxfan": 23,
  "route_option": 1
}
```

GPRJ 保存工程文件列表及器件信息，没有保存本次 place/route 等运行选项，因此直接使用 IDE 默认选项不等同于本次合格构建。完整选项和原始构建信息见 `V2/native/RESULT.json`，实际执行的脚本为 `V2/native/build_native.tcl`。复现时使用未改动的 `tools/build_native.py`，指定本机实际可用的编译器路径，并显式使用上列同一组 options、原 50 MHz SDC 和原 CST。归档 TCL 保留了原机器的绝对路径，仅作为执行证据；不要在另一台电脑上未经路径核对直接运行。
