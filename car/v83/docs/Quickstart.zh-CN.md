# 小车 V8.3：全速轨迹、平滑转向与运行中调速

本版基于已交付的 V8.2，继续使用用户最终 V8.1 包确认的左620 / 中750 / 右980手动舵机端点，修改八条预设轨迹的速度、转向过渡和运行中调参。配套程序为 `SmartCarSteeringV83.exe`，固件身份为 `RC83`。本版包含已编译的 Windows 程序与 STM32 固件，必须成套使用。

## 已修改的问题

| 项目 | V8.3 行为 |
| --- | --- |
| 手动直行、手动转弯、八条轨迹的持续速度上限 | 普通档6，快速档16计数/5 ms |
| 轨迹速度输入 | 全部由主速度滑块控制，不再额外卡在6或弯道3 |
| 慢快慢、慢快急刹 | 快段由主滑块控制；慢段可选25% / 50% / 75%，默认50% |
| 运行中调参 | 按住F8运行，鼠标调整主滑块/慢段比例；参数在下一个约100 ms刷新周期发送 |
| 8字/S形 | 原切换点附近800 ms内平滑过渡，不再从700突跳到800 |
| 正弦轨迹 | 保持730～770转向范围，解除旧低速转舵门槛 |
| 起停轨迹 | 每次真实静止后再保持0.5秒，避免高速下未停稳就进入下一段 |
| 慢快慢尾段 | 减速并确认静止后结束，取消原固定尾部空等 |
| 反馈 | “当前目标”显示固件当下有效目标，“渐变目标”显示加减速后的目标；另显示左右实测编码器计数 |
| 手动急加速峰值 | 单独命名，仅影响手动B急加速，不再与轨迹快段混用 |

界面速度单位为编码器计数/5 ms；线协议使用Q8整数，除以256得到该速度值，不是m/s。慢段最小0.5计数/5 ms，且不超过快段。示例：主速度16、慢段50%时，慢快慢为8→16→8；选择25%则为4→16→4。普通档主速度6、50%时为3→6→3。主滑块能设到16不代表已确认快速档，固件按已确认档位限制速度。

## 八条轨迹

下表的时间为规划阶段时间。初始停车转向准备、实际减速和静止确认可能使总体运行时间更长；运行中调参不重启阶段，不延长硬截止时间。

| 编号 | 轨迹 | 动作安排 | 硬截止 |
| --- | --- | --- | --- |
| 1 | 左圆 | 舵机700，行驶8秒 | 14秒 |
| 2 | 右圆 | 舵机800，行驶8秒 | 14秒 |
| 3 | 8字 | 左/右各约4秒，切换点前后合计800 ms平滑过渡 | 14秒 |
| 4 | S形 | 约每2秒换侧，每次切换点前后合计800 ms平滑过渡 | 14秒 |
| 5 | 起停 | 行驶2秒→减速至静止并保持0.5秒→行驶2秒→减速至静止并保持0.5秒 | 20秒 |
| 6 | 慢快慢 | 慢1.5秒→快3秒→慢1.5秒→减速静止结束 | 12秒 |
| 7 | 慢快急刹 | 慢1秒→快2.5秒→最长150 ms制动 | 9.65秒 |
| 8 | 正弦 | 原730～770平缓转向序列，行驶8秒 | 14秒 |

圆、8字、S形和正弦名称表示转向规划。当前系统没有位置/航向轨迹闭环；速度加快会改变行驶距离与实际形状，不能保证不同车速下仍走同样大小的圆或8字。普通/快速持续PWM上限为50%/80%；快速档6/7号快段起始可用最长250 ms的原加速增强，目标仍不超过主滑块的16。

## 如何使用全速轨迹和实时调速

1. 烧录本版固件后，打开 `SmartCarSteeringV83.exe`。默认是离线模拟；需要实车时自行选择BLE和自己的设备。
2. 停车时启用快速档，等待窗口确认，再把主速度调到目标值，最大16。普通档最大6。
3. 选中轨迹；对慢快类轨迹，选择25% / 50% / 75%慢段比例。
4. 按住F8运行所选轨迹，同时用鼠标调整速度/慢段比例。松开F8即撤销动作并停车。原鼠标按住按钮的运行方式也保留，鼠标离开或松开即取消鼠标动作。
5. 切换轨迹、失去窗口焦点、STOP、断链或故障会取消动作；恢复后必须先松开再重新按下，不自动续跑。一次轨迹完成后，继续按住不会启动第二次。

滑块更新使用独立U命令，只更新当前轨迹参数。它不会重新开始轨迹、重置阶段、延长250 ms加速窗口或硬截止。状态数值中的“当前目标”可能与滑块不同：准备转向、停车段和制动时是0，慢段按比例降低，快速档尚未确认时受普通档上限约束；“渐变目标”反映加减速过程。实测编码器反馈用于核对车轮转速，仍不是接地车速。

## 舵机端点与手动控制

手动端点保持左620 / 中750 / 右980，左右行程分别为130和230。100%手动幅度为620/980，50%为685/865；比例范围10～100%。键盘、方向键、前进/后退左右组合按钮共用同一端点计算。

有效本机配置优先，路径仍为 `%LOCALAPPDATA%\SmartCarSteeringV8\steering_limits.json`。无配置时默认620/980，错误配置提示后回退620/980。软件验证使用隔离的临时配置。本版不会覆盖正式端点配置。若以后明确需要恢复确认值，可自行运行 `apply_confirmed_limits.ps1` 后重开窗口。

手动转弯继续普通6 / 快速16。任何手动舵机目标变化，包括微小调整，仍先停车，等待编码器静止、舵机到位并稳定至少200 ms，再加速。预设轨迹内受控的连续小转向允许在运行中跟随；初始和意外的大角度跳变仍进入停车准备。

## 烧录指令

即使已经刷入V8.2，这次也需要烧录RC83；只更新电脑窗口无法改变旧固件的轨迹限速和阶段逻辑。关闭旧窗口，支撑后轮离地，关闭倒立摆驱动。S1关闭、USB拔掉后，将BOOT0接3.3V，BOOT1保持GND。接CH340 MiniUSB与原电池，再打开S1。

先查询当前CH340端口：

```powershell
Get-CimInstance Win32_SerialPort | Select-Object DeviceID, Name
```

`COM15`为示例，替换为当前CH340实际端口：

```powershell
$car = 'D:\桌面\小梅哥ACG525型国产高云FPGA教学开发板\10_学习笔记\SmartCar_Steering_V8_3_Trajectory_20261017'
powershell -NoProfile -ExecutionPolicy Bypass -File "$car\flash.ps1" -Mode Flash -Firmware V83 -Port COM15 -ReadFactoryInfoViaRam
```

保留 `-ReadFactoryInfoViaRam`。Python默认 `E:\Python\python.exe`。按脚本两次提示分别按STM32 RESET并回车；RAM信息阶段只按RESET，不拔USB、不断电、不改跳帽。脚本使用原ROM loader和RAM helper，先校验芯片与固件、完整双读备份，再擦写涉及扇区并读回验证。

看到 `PROGRAM_VERIFIED` 且脚本正常结束后：关闭S1、拔USB，BOOT0恢复GND（BOOT1仍GND），再上电。然后启动：

```powershell
Start-Process -FilePath "$car\SmartCarSteeringV83.exe"
```

## 验证与保护

交付要求原生C控制器测试、C/Host合同集成、Windows Host回归（含F8和滑块）、离线标定CLI、烧录参数替身、ARM向量/镜像/source哈希、EXE嵌入源码、实际EXE离线启动与独立审阅均通过。最终结果见 `reports`；测试中的合成编码器包含16计数/5 ms高速场景，不是实车测量。

500 ms运动租约、看门狗、堵转保护、停车回中、最长150 ms制动、手动B最高24计数/5 ms / 90% PWM / 250 ms单次限制保留。标定C1/C0锁也拒绝新增U命令。运行错误继续在现有BLE连接上重新验证；真实断链可重新连接用户已选设备，但不自动ARM或重放动作。

本次交付流程不连接小车、不扫描BLE、不烧录、不执行实车运动。最大接地车速、转弯半径与制动距离需上车确认。

当前约定见 `docs/API-Contract.md`；回退见 `Recovery.zh-CN.md`。`docs/v81_history`、`docs/v82_history`以及 `reports/baseline_v82` 为历史资料，其中旧版本限速和“无需烧录”说明不适用于V8.3。解压ZIP后可运行 `python scripts/verify_release.py` 核对完整清单，无需重新编译即可使用已提供的EXE和固件。
