# SG21 / SA21 Host 适配实施计划

用户已依据交付核对报告要求修改当前上位机。本计划采用报告中的本机 HTTP 方案，保留当前工作区的模型、挂载和布局改动，直接在当前工程落实；不创建分支、不提交已有改动。

目标：网页可通过交付中对应 Host 观察真实数据、提交显式操作并区分 ACK 与实际读回。Host 继续独占 COM；不改变固件、控制算法或其参数默认值。

接口：FastAPI `/snapshot` 与 WebSocket 返回 `latest`/`data`（显示状态）、`history`/`samples`（新采样）、`reset`（数据源切换）。样本带唯一 `sample_id` 与 `channels`，分别保留角度页和 PWM 页的设备时间及本机接收时间。`/command` 接收 Host 的 `action/request_id/name/value`，只转发一次。`/config` 管理本机桥端口和预期版本。网页不请求连接串口。

验收：身份不支持或与预期版本不符时不允许普通写操作；STOP 可发送给已识别的受支持 Host。重复 HTTP 快照不产生新波形样本，断流不产生假在线/假零，页时间不混用。PID 恢复必须包含交付要求的九项，逐项写入/读回仍由 Host 原引擎负责。SA21 JSON 完整交给原 Host 来源筛选，不生成 Ku/Tu 或自动启用模式。请求超时保留 ID、标记结果未知、不重发。所有验证均使用离线 fixture；不启动 COM/JTAG 或运行实机动作。

验证结果：后端 20 项、前端 31 项、原配套 Host 44 + 48 项均通过；两版真实本机 HTTP/ASGI 链路离线验证通过。浏览器用 fixture 覆盖三种分辨率、九项 PID、状态确认、断流、超时不重发、SA 配置文件只读载入。独立代码审查发现的分页恢复、请求等待和 ID 查询问题均已用先失败后通过的回归修复，最终复核未发现剩余重要问题。未执行任何实机连接或操作。
