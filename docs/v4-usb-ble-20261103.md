# V4 USB＋蓝牙双连接：变化与接入记录

**后续电脑端覆盖包：** 已接入连续六键修复。蓝牙副路位置确认异常时隔离蓝牙位置路，旧命令结果未知且不重发，故障前尚未发送的蓝牙位置请求丢弃；用户随后新按的位置键走 USB。重新启用蓝牙位置路需手动断开并重连蓝牙。该修复不改位流，也不代表蓝牙 CRC 丢包根因已解决；来源见 [Host 说明](../host/v4_usb_ble/README.md)。

## 相对上一版 `56345239` 的变化

| 项目 | 上一版 V4 R28 | 本次 `5634523A` |
| --- | --- | --- |
| 连接 | BLE 单链路 | USB 主路和 BLE 可同时连接；同一 Host、同一会话和请求编号空间 |
| 操作路由 | BLE | 普通控制、参数、数据主要走 USB；位置与保持优先走就绪的 BLE，BLE 未就绪时新提交的请求走 USB |
| 停止 | 原 BLE 停止 | USB 与已连接 BLE 使用相同逻辑事件发送 STOP/ESTOP；动作结果未知时不换路重发 |
| 帧与身份 | wire4、variant4、schema `56345208`、layout5，固件 `56345239` | 帧布局和 schema 保持，固件身份改为 `5634523A`；不能将两者当作同一固件 |
| 现场输入 | 精简蓝牙窗口 | USB/BLE 分别连接、显示状态；可配置 COM、波特率、BT10 地址及六个窗口按键；可选指定键盘并保存本机设置 |

默认六个相对位置、手动平衡、停止、停机抓零与 PID 读写仍按原 Host 的条件执行，无自动起摆。S1 默认参数仍为角度 `53.78 / 0 / 210.14`、位置 `17.67 / 0 / 616.61`。角 P/位置 P 周期为 1/5 ms，角 D/位置 D 为 5/25 ms，数据标称上传 200 Hz；积分固定为零。

独立比对原工程发现：`forest_d1_system.v` 增加 USB 收发并接到原路由器，`forest_d1_link.v` 将完整遥测快照锁存在发送队列前，避免发送期间混入后续事务；`forest_d1_top.v` 的变化为注释。交付的源码差异记录显示控制器和保护相关文件未变化。新旧 Host 中共同的 2,124 个交付文件有 2,112 个相同、12 个不同；新 Host 另有双链路、串口、设置与键盘等文件。

## 当前项目如何使用

1. 根据现场设备实际固件选择匹配位流。新文件为 `firmware/releases/20261103/V4_USB_BLE_5634523A.fs`，没有在本轮自动烧录或连接硬件。新旧文件 SHA-256 不同；SRAM 加载断电后可能失效。
2. 双击 `START_HOST.bat` 选择 2，在原 Host 窗口手动选择 USB 串口，默认波特率 230400，再按需手动连接 BT10。也可只连接蓝牙；蓝牙作为主连接时，需先停止并断开全部才能改用 USB 主路。原窗口支持配置按键和指定键盘，电脑端设置由用户选择保存。
3. 运行 `START_SHOWCASE.bat`，网页自动识别或选择 `V4 USB + 蓝牙`。网页分别显示 USB/BT10 连接和回包状态；命令与波形均通过原 Host，不另开串口或建立第二会话。如果先前网页固定选择了旧 `V4_R28`，需在“参数与连接”中改为自动识别或新版并保存。
4. 网页额外要求 `3A` 匹配回包和当前会话的主路诊断帧后才显示已同步并允许普通控制。原交付 Host 本身可在短回包就绪后工作；若长诊断未到，网页会继续等待。停止和急停仍可在已连接时请求。

已保存旧 `56345239` 及其 Host。若需旧版离线追溯，可在项目根目录执行 `host\v4_r28\PC_Bluetooth\runtime\python.exe -B -X utf8 launch_host.py V4_R28`。新 `ForestD1.Raw.v2` 日志也可通过 `launch_host.py V4_USB_BLE --replay <日志.zip>` 只读回放：只展示带身份的诊断帧，不推断无会话证据的 compact 帧，也不执行日志里的命令。

## 来源与验证边界

原 ZIP SHA-256 为 `650468afac7c6df482a7e184d7149ccb7ff5f8cc6d4e646e6b06a597b9c38722`；包内清单 2,235 项均通过字节数和 SHA-256 校验。新位流 SHA-256 为 `115a160ec7794a4929ab7a58cc33bfd353ed93171396c1083f080aad3077454e`。`PC_Bluetooth/VERSION.json` 中旧 `firmware` 字段仍写 `56345239`，其 `usb_bluetooth_firmware` 字段、位流和实际帧均指向 `5634523A`，因此不能只看前者判断本次位流。

随包记录描述曾在交付方电脑将 `3A` 加载到 SRAM，并观察到 USB、蓝牙共用会话和人工发出的定位请求；这是交付方的历史记录，不代表本次在当前设备重新验收。随包一个双路快照同时记录 `fault=1`、`rx_errors=1` 和累计 `telemetry_dropped=7307`，因此不能把链路有回包理解为已完成长期稳定性、机械跟踪精度或故障恢复验收。部分早期结果字段仍写“未烧录”，后补字段与实机记录表明交付方曾做过 SRAM 操作；不同时间点应分别理解。

本项目测试使用离线帧、模拟链路和配套程序的离线检查，不打开真实 COM/BLE、下载位流、校零或发送机械动作。现场仍需由操作者核对设备身份、观察两路回包、检查故障和日志，再按现场流程验证停止、方向及运动效果。
